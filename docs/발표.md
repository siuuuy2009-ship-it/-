# 다시, 나눔 — 3분 발표

## 1. 실생활 문제 · 약 30초

학기가 끝나면 아직 쓸 수 있는 참고서, 교복, 생활용품이 남습니다. 필요한 학생이 있어도 물품마다 개별적으로 배정하면, 특정 물품만 필요한 학생이 받지 못하고 다른 물품은 남을 수 있습니다. 저희는 학교의 공동 나눔 행사에서 전체 신청을 모아 배정하는 앱을 만들었습니다.

## 2. 알고리즘 선정 · 약 50초

물품을 왼쪽 그룹, 신청자를 오른쪽 그룹으로 나누었습니다. 종류와 상태, 수령 조건이 맞고 해당 물품을 신청한 경우에만 선을 연결합니다. 물품당 한 명, 신청자당 한 개라는 제한에서 가장 많은 연결을 선택하는 최대 이분 매칭을 사용했습니다.

예를 들어 민수는 참고서 A와 B 모두 괜찮고 지수는 A만 필요합니다. 민수에게 A를 먼저 주면 지수는 받지 못하고 B는 남습니다. A를 지수에게 주고 B를 민수에게 주면 두 명 모두 받습니다. 증가 경로를 찾아 확정 전 임시 배정을 바꾸는 것이 핵심입니다.

## 3. 앱 시연 · 약 60초

1. ‘나눔 물품’에서 등록된 참고서와 물품 상태를 보여 줍니다.
2. ‘참여자·신청’에서 받을 수 있는 물품을 여러 개 선택하는 구조를 보여 줍니다.
3. ‘자동 매칭’에서 예시 자료의 순차 배정 3명과 최대 이분 매칭 6명을 비교합니다.
4. 신청을 마감하고 배정을 확정합니다. 실제 전달과 계산 결과를 구분하기 위해 전달 확인을 별도로 합니다.
5. ‘알고리즘 이야기’에서 ‘신청 조건 → 순차 배정 → 최대 이분 매칭’ 버튼을 눌러 선이 달라지는 모습을 보여 줍니다.

## 4. 검증과 기대 효과 · 약 40초

알고리즘은 양쪽 정점이 각각 0~4개인 74,963개 그래프에서 완전탐색으로 구한 최댓값과 비교했습니다. 또한 한 사람이 중복 배정되지 않는지, 확정한 결과가 바뀌지 않는지, 조건에 맞지 않는 물품을 제외하는지 검사했습니다.

이 앱이 보장하는 것은 현재 등록된 자료와 조건에서의 최대 배정 건수입니다. 모든 상황에서 순차 배정보다 더 많은 건수를 만드는 것은 아니며, 공정성이나 선호도를 최적화하는 것은 아닙니다. 앞으로 실제 학교 행사에 적용해 전달 완료율을 측정하고, 학생별 계정과 공동 참여 기능을 추가할 수 있습니다.

## 예상 질문

**당근과 무엇이 다른가요?**

나눔이라는 소재는 겹칩니다. 저희는 학교 행사 전체의 물품과 신청을 한꺼번에 고려해 배정하는 문제를 해결합니다. 같은 자료에서 개별 순차 배정과 최대 이분 매칭을 비교하여 그 차이를 보여 줍니다. 당근의 내부 알고리즘을 추정하거나 없는 기능이라고 단정하지 않습니다.

**왜 이분 매칭인가요?**

서로 다른 두 그룹인 물품과 신청자 사이에서 조건에 맞는 일대일 연결을 최대한 많이 선택하는 문제이기 때문입니다.

**한 사람이 여러 물품을 나눔할 수 있나요?**

가능합니다. 나눔자 대신 물품 한 개를 정점으로 잡았습니다. 받는 것은 회차당 최대 한 개입니다.

**가장 필요한 사람에게 주나요?**

현재는 등록한 조건을 충족하는 배정의 개수를 최대화합니다. 필요성의 정도나 공정성은 별도 정책과 알고리즘이 필요한 확장 과제입니다.

**지금 바로 여러 학생이 각자 접속할 수 있나요?**

현재는 운영자가 자료를 입력하는 MVP입니다. 브라우저마다 별도 작업 공간을 사용합니다. 학생별 계정과 공동 행사 참여는 후속 개발 범위입니다.
