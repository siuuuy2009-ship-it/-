# 학생 로그인

Vercel의 `/api/school`은 기존 `DATABASE_URL`을 사용합니다. 비밀번호나 학생 명단을 소스 코드에 넣지 않습니다. 기존 익명 시연 공간과 학교 자료는 분리되어 있습니다.

## 운영자

1. 로그인 화면의 **처음 운영하는 나눔함 만들기**에서 운영자 계정을 만듭니다.
2. **명단 관리**에서 `학번,이름` 형식의 CSV 또는 텍스트 명단을 등록합니다. 같은 학번·이름은 중복 등록되지 않습니다.
3. 발급한 초대코드 CSV를 내려받아 각 학생에게 본인의 코드 또는 가입 링크만 전달합니다. 전체 파일을 학생에게 공유하지 않습니다.
4. 신청 마감, 배정 확정, 전달 확인은 운영자 계정에서 진행합니다. 새 행사를 시작해도 학교 명단과 계정은 유지됩니다.

초대코드는 30일 동안 한 번만 사용할 수 있습니다. 코드를 잃어버리거나 학생이 비밀번호를 잊으면 운영자가 **재발급**합니다. 재발급하면 해당 학생의 이전 로그인과 비밀번호가 해제됩니다.

## 학생

초대코드로 학번과 새 비밀번호를 등록합니다. 이후 학교코드·학번·비밀번호로 로그인하며, 가입 링크로 들어오면 학교코드가 입력됩니다. 본인의 물품과 신청만 수정할 수 있습니다. 다른 학생의 이름과 학번은 배정 확정 후 본인과 연결된 상대인 경우에만 표시됩니다.

비밀번호는 salt가 다른 scrypt 해시로, 초대코드와 로그인 세션은 SHA-256 해시로 저장합니다. 로그인 쿠키는 HttpOnly, SameSite=Strict이며 HTTPS에서 Secure를 사용합니다. 로그인은 7일 후 만료되며 서버에서 로그아웃과 재발급을 확인합니다. 로그인 시도 제한은 PostgreSQL에 저장되어 서버리스 인스턴스끼리 공유됩니다.

## 검증과 로컬 실행

```powershell
node --test tests/*.test.ts
node node_modules/vite/bin/vite.js build --config vite.vercel.config.ts
node scripts/preview-school.mts
```

로컬 미리보기는 `work/school-preview/`에 별도 PostgreSQL 자료를 저장합니다. 표시된 주소를 `TEST_BASE_URL`로 설정한 뒤 `node scripts/test-school-api.mjs`를 실행하면 별도 검증용 학교에서 가입·공유·권한·매칭·로그아웃을 확인합니다.

`scripts/setup-school.mjs`는 `work/`의 비공개 명단을 읽고 초기 운영자와 초대코드를 준비합니다. 로그인 정보와 발급한 코드는 `work/school-roster/`에만 저장됩니다. `work/`는 Git에서 제외되며, 개인정보나 실제 코드를 GitHub에 올리지 않습니다.
