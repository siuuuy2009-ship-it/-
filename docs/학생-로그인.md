# 학생 로그인

Vercel의 `/api/school`은 기존 `DATABASE_URL`을 사용합니다. 비밀번호나 학생 명단을 소스 코드에 넣지 않습니다. 기존 익명 시연 공간과 학교 자료는 분리되어 있습니다.

## 운영자

1. 로그인 화면의 **처음 운영하는 나눔함 만들기**에서 개인정보 안내에 동의한 뒤 운영자 계정을 만듭니다.
2. **동의·가입 관리**에서 학생 정보를 입력하지 않고 필요한 수만큼 익명 초대코드를 발급합니다. 명단 일괄 업로드 API는 차단되어 있습니다.
3. 발급한 초대코드 CSV를 내려받아 각 학생에게 본인의 코드 또는 가입 링크만 전달합니다. 전체 파일을 학생에게 공유하지 않습니다.
4. 신청 마감, 배정 확정, 전달 확인은 운영자 계정에서 진행합니다. 나눔함 초기화를 시작해도 학교 명단과 계정은 유지됩니다.

초대코드는 30일 동안 한 번만 사용할 수 있습니다. 코드를 잃어버리거나 학생이 비밀번호를 잊으면 운영자가 **재발급**합니다. 재발급하면 해당 학생의 이전 로그인과 비밀번호가 해제됩니다.

## 학생

초대코드로 본인 이름·학번과 새 비밀번호를 입력합니다. 개인정보 수집 항목, 목적, Vercel/Supabase 서버 저장, 보유 기간, 거부 권리를 안내한 뒤 기본 해제된 필수 체크박스에 직접 동의해야 가입 요청이 전송됩니다. 서버도 동의 값이 정확히 true이며 현재 안내 버전과 일치하는지 확인합니다. 동의 시각과 안내 버전은 계정에 저장됩니다.

초대코드는 특정 학번에 사전 연결되지 않습니다. 배부 기록은 운영자가 로컬에서 관리하고, 가입 후 입력된 이름·학번을 확인해야 합니다. 학생은 이후 학교코드·학번·비밀번호로 로그인하며, 본인의 물품과 신청만 수정할 수 있습니다. 다른 학생의 이름과 학번은 배정 확정 후 본인과 연결된 상대인 경우에만 표시됩니다.

학생은 **계정·정보 삭제**에서 현재 비밀번호와 삭제 확인을 입력해 동의를 철회할 수 있습니다. 서버는 학생의 계정·세션·사용한 초대코드와 현재 나눔 모음에 연결된 이름·학번, 물품, 신청, 배정을 하나의 작업으로 삭제합니다. 삭제된 물품의 다른 학생 배정도 취소됩니다.

비밀번호는 salt가 다른 scrypt 해시로, 초대코드와 로그인 세션은 SHA-256 해시로 저장합니다. 로그인 쿠키는 HttpOnly, SameSite=Strict이며 HTTPS에서 Secure를 사용합니다. 로그인은 7일 후 만료되며 서버에서 로그아웃과 재발급을 확인합니다. 로그인 시도 제한은 PostgreSQL에 저장되어 서버리스 인스턴스끼리 공유됩니다.

## 기숙사에서 부탁하고 나누기

‘필요해요’에는 필요한 물품 이름·종류·부탁 내용을 적습니다. 부탁 글의 ‘이 물품 나눠요’를 누르면 해당 이름·종류가 채워진 물품 등록 창이 열립니다. 필요한 학생은 실제로 등록된 물품을 확인하고 수령 가능한 후보를 선택해 신청합니다. 글만 올리는 것으로 자동 배정되지는 않습니다. 부탁 글의 해결 표시는 작성자나 운영자가 할 수 있습니다.

운영자가 모인 신청의 배정과 전달을 확인하고 ‘다음 나눔 이어가기’를 누르면 전달된 물품과 배정을 정리하고 남은 물품·미배정 신청·부탁 글은 유지합니다. 전달 대기 중인 배정이 있으면 먼저 완료하거나 취소해야 합니다. 계정·정보 삭제는 본인의 부탁 글도 삭제합니다.

## 매너 점수

학생 프로필에는 기본 50점의 매너 점수와 받은 평가 수를 표시합니다. 전달 완료된 물품의 나눔자와 수령자만 서로 한 번씩 평가할 수 있으며, 좋았어요 +2점, 보통 0점, 아쉬웠어요 -2점으로 0~100점 범위에 반영합니다. 이 점수는 이분 매칭의 배정 기준으로 사용하지 않습니다.

평가 화면에서 별도 저장 안내를 확인하고 저장해야 합니다. 서버는 로그인한 평가자를 기준으로 상대를 결정하고, 직접 참여하지 않은 나눔·전달 전·중복·자기 평가를 거부합니다. 원본 평가값과 평가자 이름은 공개하지 않고, 합산 점수와 평가 수만 표시합니다. 나눔함 초기화에서도 점수는 유지되며, 계정·정보 삭제 시 해당 계정이 남기거나 받은 평가도 삭제됩니다.

## 보고서용 가상 시연

`https://dasi-nanum.vercel.app/?demo=classroom` 또는 로그인 화면·계정 상단의 **보고서용 가상 시연**에서 이용합니다. 운영자와 가상 학생 6명의 화면을 선택하고, 신청 접수·배정 확정·전달 완료 장면을 바로 불러올 수 있습니다. 최대 이분 매칭, 학생 본인 물품·신청 관리 및 상대 매너 평가를 같은 화면과 업무 규칙으로 체험합니다.

모든 이름과 학번은 가상 예시이며 로그인한 실제 학생을 나타내지 않습니다. 자료는 현재 브라우저 화면의 메모리에서만 다루고 서버·실제 학교 나눔함에 저장하지 않습니다. 사용자 전환 시 시연 작업은 유지하고, 장면 선택·초기화·새로고침 시 예시 자료로 돌아갑니다. 실제 학생 계정은 기존대로 학생 본인이 초대코드로 동의 가입해야 합니다.

## 검증과 로컬 실행

```powershell
node --test tests/*.test.ts
node node_modules/vite/bin/vite.js build --config vite.vercel.config.ts
node scripts/preview-school.mts
```

로컬 미리보기는 `work/school-preview/`에 별도 PostgreSQL 자료를 저장합니다. 표시된 주소를 `TEST_BASE_URL`로 설정한 뒤 `node scripts/test-school-api.mjs`를 실행하면 별도 검증용 학교에서 가입·공유·권한·매칭·로그아웃을 확인합니다.

`scripts/setup-school.mjs`는 기존 운영자 계정으로 로그인하여 익명 코드 발급 수만 서버에 전송합니다. 명단의 이름·학번은 전송하지 않고 로컬에서만 코드와 연결하여 배부용 CSV를 만듭니다. 운영자 계정 신규 생성은 앱의 동의 화면에서 진행해야 합니다. `work/school-roster/`의 명단·로그인 정보·초대코드는 Git에서 제외됩니다.
